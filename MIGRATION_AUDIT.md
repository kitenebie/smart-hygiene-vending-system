## Latest PHP changes

1. `index.php` adds “Reset coin balance” actions on Device Health and Settings, plus a current-credit status label in Settings.
2. `assets/js/app.js` loads reset status on Health/Settings, displays the latest credit parsed from ESP32 logs, confirms the reset, and posts to `api/credit_reset.php`.
3. New `api/credit_reset.php` returns `credit_reset_token` and latest reported credit on GET. POST increments the token in Supabase and local MySQL, then records a notification.
4. New `includes/functions.php` provides shared helpers, adds/reads `credit_reset_token`, and parses recent credit from `esp32_logs`.
5. `includes/supabase_sync.php` pulls 12 tables plus PIN assignments from Supabase into local MySQL, maintaining incremental IDs for transactions, health/resource logs, and ESP32 logs. The PHP UI calls the missing `api/supabase_sync.php` every 30 seconds, then reads its MySQL backup if sync fails. React queries Supabase directly and has no MySQL/offline snapshot fallback; the endpoint implementation is absent, so its exact runtime behavior cannot be verified. The backup path is not recreated because the migration target has no PHP/MySQL application backend.
6. `api/settings_get.php` and `api/settings_save.php` handle the existing Wi-Fi settings behavior.

## Data/import status and remaining gaps

The import generator and `supabase/ONE_TIME_SETUP.sql` use the isolated Nov 12 dump, preserve IDs, convert booleans, exclude demo seeds/the superseded dump, and use `ON CONFLICT DO NOTHING`. The current full bundle passed twice on fresh local PostgreSQL 17 with minimal Supabase Auth/Realtime fixtures; all 15 source-table counts matched. Standard migration 065 adds a profile-checked settings read RPC that omits the Wi-Fi password. Standard migration 066 enables role-scoped transaction reads and keeps the existing device `complete_vend` RPC working; disposable PostgreSQL checks verify profile access, anon denial, direct-write denial, and device vending. Standard migration 067 adds role-scoped reads for health logs and notifications, allows only the existing firmware anon POST columns, and preserves authenticated notification create/mark-read actions; disposable PostgreSQL checks cover those paths. Migration 068 protects `admins` and `supabase_sync_state` from browser roles and removes the legacy plaintext password default. Migration `20261114002000` hashes plaintext credentials in place, preserves existing bcrypt hashes, and passes a disposable conversion/verification test. Migration 069 enables RLS on `machine_settings`, blocks anon writes, and scopes app reads/updates to Administrator/Machine Technician profiles; tests verify repeat application, app permissions, and unchanged firmware `select=*`. That compatibility read still exposes the machine settings row—including Wi-Fi password and device API key—to anyone with the anon key. A device-key read RPC is the path to remove that exposure, but it requires a future firmware API rollout and is not in the bundle. Firmware health/notification POSTs also remain forgeable because the existing requests contain no device key; key-checked writes in migration 100 remain deferred. Other direct firmware REST paths for slots, GCash, and SMS still depend on the anon key. Candidate migrations 070–100 remain under `supabase/deferred_migrations/`, excluded from `ONE_TIME_SETUP.sql`, and not deployed. The regenerated bundle includes 065–069 and `20261114001000`–`04000` and passed a fresh PostgreSQL application twice. RLS is enabled on `slots` with anon read-only access for the existing firmware GET; RLS remains disabled on `gcash_payments` and `sms`. The actual React `loadReportedCoinBalance()` helper returned a finite value from live Supabase. Current read-only schema probes recognize `machine_settings.credit_reset_token` and `gcash_payments.Notes`; an anonymous reset RPC call is denied with 401/42501. Anonymous HEAD/count probes found visible rows in `slots`, `transactions`, `machine_settings`, `machine_health_logs`, `gcash_payments`, `notifications`, and `sms`; no remote row bodies were fetched. Remote migration history, imported row counts, and a successful admin RPC remain unverified. Do not apply the current bundle to production; remaining policies and exposed device credentials need a staged firmware-compatible rollout.
