# PHP ↔ React module parity

| PHP page/module | React equivalent | Current parity/gap |
|---|---|---|
| Login/session | `LoginPage`, `AuthProvider` | React currently uses Supabase Auth/`profiles`, while the user's instruction requested the legacy `admins` table; this is unresolved. PHP auth files are missing. Email format is validated in-browser, but that is not login parity. |
| Overview/analytics | `OverviewView` | UI/data path exists; PHP endpoint source missing. |
| Slots/inventory/restock | `SlotsView`, ESP32 firmware | React restock uses the role-guarded RPC. Candidate profile/device RLS and slot/vend RPCs pass disposable PostgreSQL tests, but are deferred; current firmware REST APIs are preserved. Live migration/data and hardware remain unverified. |
| Transactions/GCash approval/export | `TransactionsView`, ESP32 firmware | PHP requests 30 recent transactions and has no table search/filter; React also requests 30. Migration 066 role-scopes reads and preserves `complete_vend`; disposable DB tests cover transaction reads, deferred GCash device-key RPCs, and authenticated approval. Migration 090 is not deployable with the current firmware, which still directly POSTs/GETs `/rest/v1/gcash_payments`; it revokes anon table access. React CSV quoting/formula safety is tested. Authenticated UI, notification effects, live RLS, and missing PHP export parity remain unverified. |
| Device Health | `HealthView`, ESP32 firmware | Telemetry/history and admin-only coin reset exist. Standard migration 067 role-scopes reads and preserves the existing firmware POST with anon insert-only access; disposable PostgreSQL tests pass. Key-checked write RPC remains deferred; live migration and hardware verification pending. |
| Notifications/read-all | `NotificationsView`, ESP32 firmware | React read/mark-read and app insert actions exist. Standard migration 067 role-scopes reads, preserves the firmware POST with anon insert-only access, and tests profile actions. Key-checked firmware RPC remains deferred; live migration/realtime behavior unverified. |
| SMS logs | `SmsLogsView` | PHP UI has no search/filter/pagination controls; React shows the newest 100 and refreshes through polling/Realtime. PHP `api/sms_logs.php` is missing, so query-limit parity and live outbox behavior remain unverified; firmware still uses direct REST. |
| ESP32 logs | `Esp32LogsView` | PHP UI has no table filters/pagination; React loads the newest 250 with polling/Realtime. Additive migration restricts reads to profiled users; live migration and query-limit parity remain unverified because the PHP API source is missing. |
| ESP32 PIN status, assignment, device catalog | Settings + `Esp32PinStatusModal` | Additive RLS and RPC guards allow authenticated Administrator/Machine Technician profiles; disposable PostgreSQL tests cover reads, creation, assignment, validation, and anon denial. Live migration and authenticated UI remain unverified; PHP endpoint source is missing. |
| Product/slot settings | `SettingsView` | Product name/capacity controls exist. |
| Machine settings | `SettingsView`, ESP32 firmware | Standard migration 069 allows admin/technician reads and writes, denies anon writes, and preserves the unchanged firmware GET. Disposable tests cover all settings fields, blank-password preservation, role boundaries, repeat application, and `select=*`. That GET still exposes Wi-Fi password/device key to anon; device-key read RPC 070 is deferred. Live migration and hardware remain unverified. |
| Admin profile/logout | `SettingsView`, Supabase Auth | Profile UI exists; password changes preserve the exact entered value and pass a regression assertion/build. PHP profile/auth source is missing; auth-table choice remains unresolved; live email/password update is unverified. |
| Legacy admin/sync data | Supabase tables `admins`, `supabase_sync_state` | Migration 068 denies browser-role access and removes the legacy admin password default; fresh-bundle PostgreSQL assertions pass. React login still uses Supabase Auth/`profiles`, not the requested `admins` table. |
| Coin-balance reset | Health + Settings | Additive schema, admin-authorized RPC/notification, React controls, and ESP32 persistent token consumer implemented; Supabase and device verification pending. |
| `gcash_payments.Notes` | None | No use found in either frontend; migrate data column only unless intended behavior is identified. |
| MySQL ↔ Supabase sync fallback | None | React queries Supabase directly; legacy sync API implementation is missing. |
| CSV export | `TransactionsView` | Client-side serializer/download passes delimiter, quote, newline, formula-injection, filename, and empty-data checks. PHP links to missing `api/transactions_export.php`, so exported-row/column parity is unverified. |

PHP nav has eight dashboard views and React has all eight. Coin reset parity is implemented locally; remaining gaps include remote migration verification and PHP backend behavior whose source files are missing.
